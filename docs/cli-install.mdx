The CLI is `amperstand` — a tiny HTTP client (~5 MB install, two dependencies). Use it once you have a [server running](/quickstart).

## 1. Install

`amperstand` is a Python CLI. Pick whichever installer matches your habits — they all end up with the same `amperstand` binary on your `$PATH`.

<CodeGroup>

```bash pipx (recommended)
# pipx isolates each CLI in its own venv, so amperstand can't break (or be
# broken by) anything else you've got installed. On macOS: `brew install pipx`.
pipx install amperstand
```

```bash uv
# Fast Rust-based installer. Same venv isolation as pipx.
uv tool install amperstand
```

```bash pip
# Standard pip — works fine, but installs into your active Python env.
# If you've never thought about this and don't have pipx, this is OK.
pip install amperstand
```

```bash Docker
# Run the CLI as a one-shot container. Good for CI / scripts where you
# don't want a Python install at all.
docker run --rm -e AMPERSTAND_API_KEY \
  -v ~/.amperstand:/root/.amperstand \
  ghcr.io/zkid18/amperstand:latest <command>
```

</CodeGroup>

The CLI does no extraction itself — every command translates to a REST call against your server. So no Playwright, no yt-dlp, no heavy ML libs regardless of installer.

Requires Python 3.10+. **Homebrew formula**: not on the roadmap yet — if you'd find one useful, open an issue.

## 2. Get your API key

From your server (the bootstrap script printed it; if you missed it):

```bash
ssh root@<your-server>
grep AMPERSTAND_API_KEY /etc/amperstand/env
```

## 3. Set the key in your shell

On your laptop:

```bash
# Save to a 0600 file so it doesn't sit in your shell history
echo "<the-64-char-hex>" > ~/.amperstand-api-key
chmod 600 ~/.amperstand-api-key

# Export it from your shell rc
echo 'export AMPERSTAND_API_KEY="$(cat ~/.amperstand-api-key | tr -d "\n")"' >> ~/.zshrc
source ~/.zshrc
```

## 4. Connect to the server

```bash
amperstand vault backend set-http https://your-server \
    --api-key-env AMPERSTAND_API_KEY
```

<Warning>
`--api-key-env` takes the **name** of the environment variable, not the value. The CLI stores the name in `~/.amperstand/config.json` and reads the value at runtime — so rotating the key on the server just means `export AMPERSTAND_API_KEY=<new>`. Passing the value directly leaks it into the config file.
</Warning>

## 5. Capture something

```bash
amperstand capture https://danluu.com/why-hardware-development-is-hard/
```

You should see:

```
Saved: 01JK8XQ4... — Why hardware development is hard
  vault/2026/06/why-hardware-development-is-hard.md
```

The CLI sent the URL to the server, the server extracted the markdown, persisted it, and returned the doc ID. The actual file lives on the server at `$AMPERSTAND_DATA_DIR`.

## 6. Verify the round-trip

```bash
amperstand vault status
# Server: ok
# Docs: 1
```

If you also configured `OPENAI_API_KEY` on the server, semantic search works:

```bash
curl -X POST https://your-server/v1/docs/search/semantic \
     -H "Authorization: Bearer $AMPERSTAND_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"q":"hardware development", "limit":3}'
```
