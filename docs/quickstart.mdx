Amperstand is two pieces: a **server** (`amperstand-core`) you run somewhere, and a **CLI client** (`amperstand`) you run on your laptop. This page sets up both and connects them.

You can run the server locally for the quickstart, then move it to a droplet later — see [Deployment](/deployment).

## 1. Install the server

On the machine that will hold your vault (your laptop for now, a droplet later):

```bash
pip install amperstand-core
playwright install chromium    # for JS-heavy pages
```

That's the whole server — FastAPI, uvicorn, all the extractors, sqlite-vec, embeddings. No extras needed.

## 2. Configure the server

Three environment variables:

```bash
# Auth — clients send this as Bearer
export AMPERSTAND_API_KEY="$(openssl rand -hex 32)"

# Where to put markdown + the SQLite index
export AMPERSTAND_DATA_DIR="$HOME/.amperstand-vault"

# Embeddings + hybrid-search rerank + YouTube Whisper fallback
export OPENAI_API_KEY="sk-..."
```

`OPENAI_API_KEY` is technically optional, but without it:

| Feature | Status without OPENAI_API_KEY |
| --- | --- |
| Capture (articles, YouTube transcripts, feeds, email) | Works |
| Keyword search (`/v1/docs/search`) | Works |
| Semantic search (`/v1/docs/search/semantic`) | Returns `503` |
| Hybrid search (`/v1/docs/search/hybrid`) | Degrades to FTS5-only, no rerank |
| YouTube audio-fallback transcripts | Disabled |

Embedding model: `text-embedding-3-small`, ~$0.02 per 1,000 docs. Worth it.

See [Configuration](/configuration) for every env var the server reads.

## 3. Run the server

```bash
amperstand-server
```

This is a console script that wraps uvicorn — defaults to `0.0.0.0:8765`. Override with `--host`, `--port`, or via `$AMPERSTAND_HOST`/`$AMPERSTAND_PORT`. Run `amperstand-server --help` for all flags.

You should see:

```
INFO:     Uvicorn running on http://0.0.0.0:8765
```

For production (systemd unit + Caddy + swap), see [Deployment](/deployment).

## 4. Install the CLI

In a separate terminal — or on a different machine entirely:

```bash
pip install amperstand
```

The CLI is HTTP-only and lightweight. No Playwright, no yt-dlp, no extraction code. It just speaks to the server.

## 5. Connect the CLI to the server

```bash
# Make the key available to your shell
export AMPERSTAND_API_KEY="<paste the key from step 2>"

# Point the CLI at the server (use the server's URL, not localhost if you're on a different machine)
amperstand vault backend set-http http://localhost:8765 \
    --api-key-env AMPERSTAND_API_KEY
```

<Warning>
`--api-key-env` takes the **name** of an environment variable, not the value. Passing the value directly leaks it into `~/.amperstand/config.json` and shell history. See [Authentication](/api-reference/authentication).
</Warning>

To make this survive new shells, add to your `~/.zshrc`:

```bash
echo 'export AMPERSTAND_API_KEY="<your-key>"' >> ~/.zshrc
```

## 6. Capture something

```bash
amperstand capture https://danluu.com/why-hardware-development-is-hard/
```

The CLI sends the URL to the server, the server runs the extractor, writes the markdown into `$AMPERSTAND_DATA_DIR`, and returns the doc ID. You'll see:

```
saved as 01JK8XQ4... (vault/2026/06/why-hardware-development-is-hard.md)
```

## 7. Verify search works

```bash
amperstand vault status

curl -X POST http://localhost:8765/v1/docs/search/semantic \
     -H "Authorization: Bearer $AMPERSTAND_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"q":"hardware development", "limit":3}'
```

If you get results, embeddings are live. If you get `503: semantic search disabled`, `OPENAI_API_KEY` isn't set in the server process.
