## What every client does

Three responsibilities:

1. **Hold the user's server URL + API key** (config screen, env var, settings file).
2. **POST captures to the server** when the user does something (sends a URL, clicks a button, schedules a sync).
3. **Optionally query back** — list recent docs, search, fetch a doc — to give the user feedback.

That's it. No extraction, no markdown generation, no SQLite. The server does all that.

## Minimal Python client

```python
import httpx, os

class Vault:
    def __init__(self, base_url: str, api_key: str) -> None:
        self.client = httpx.Client(
            base_url=base_url,
            headers={"Authorization": f"Bearer {api_key}"},
            timeout=120,
        )

    def capture(self, url: str) -> dict:
        return self.client.post("/capture", json={"url": url}).json()

    def search(self, q: str, limit: int = 10) -> list[dict]:
        r = self.client.post(
            "/v1/docs/search/hybrid",
            json={"q": q, "limit": limit, "rerank": True},
        )
        return r.json()["items"]

# Usage
vault = Vault(os.environ["AMPERSTAND_BASE_URL"], os.environ["AMPERSTAND_API_KEY"])
doc = vault.capture("https://danluu.com/why-hardware-development-is-hard/")
print(doc["id"], doc["title"])
```

That's the entire shape. Bot or extension code is mostly user-interaction plumbing around this 15-line core.

## Minimal JS client

```js
class Vault {
  constructor(baseUrl, apiKey) {
    this.baseUrl = baseUrl.replace(/\/$/, "");
    this.headers = {
      "Authorization": `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    };
  }

  async capture(url, { html = null, title = null } = {}) {
    const endpoint = html ? "/capture/html/async" : "/capture/async";
    const body = { url, ...(html && { html, title }) };
    const r = await fetch(`${this.baseUrl}${endpoint}`, {
      method: "POST", headers: this.headers, body: JSON.stringify(body),
    });
    return r.json();   // { job_id, status }
  }

  async pollJob(jobId, { intervalMs = 1000 } = {}) {
    while (true) {
      const r = await fetch(`${this.baseUrl}/jobs/${jobId}`, { headers: this.headers });
      const job = await r.json();
      if (job.status === "done" || job.status === "failed") return job;
      await new Promise(r => setTimeout(r, intervalMs));
    }
  }
}
```

The extension uses the async endpoints (`/capture/html/async`) so the popup can close immediately while extraction runs in the background. Then a notification fires when the job completes.

## Choosing sync vs async

| Use | When |
| --- | --- |
| `POST /capture` (sync) | Your client can wait 5–120s for the result. Server runs the extractor, returns the saved doc. |
| `POST /capture/async` + `GET /jobs/{id}` (poll) | Your client can't block. Bot popups, extension popups, mobile share-sheets. Returns a `job_id` instantly. |

Async also lets you batch — POST 20 URLs, walk away, check the queue later via `GET /jobs?status=done`.

## Conventions to match

- **Auth**: every endpoint except `/health` requires `Authorization: Bearer <key>`. Don't hardcode the key; read it from env/config.
- **IDs**: doc IDs are 26-char ULIDs (sortable, URL-safe). Don't assume integer IDs.
- **Idempotency**: `/capture` is idempotent on source URL. Re-sending the same URL returns the existing doc, not a duplicate.
- **Errors**: 4xx = caller fix (bad URL, missing field, auth). 5xx = server tried and failed. Don't auto-retry 4xx.

## Things you don't have to think about

- **Extraction logic** — the server picks the right extractor (trafilatura, yt-dlp, transcript API, fxtwitter rewrite) from the URL shape.
- **Deduplication** — server handles it via `body_hash`.
- **Embedding generation** — happens at capture time if the server has `OPENAI_API_KEY`.
- **File storage** — the server writes markdown to `$AMPERSTAND_DATA_DIR`. Your client never touches files.

All of that is server-side. Your client just calls HTTP and renders the response.
