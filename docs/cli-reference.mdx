The `amperstand` CLI is an HTTP client for an `amperstand-core` server. Install with `pip install amperstand`. It does no extraction itself — every command translates to a REST call against the server you've configured.

## See every command at once

```bash
amperstand commands
```

```
amperstand
├── capture       — Send a URL to the server for capture.
├── commands      — Print every command in the CLI, in one flat tree.
├── config        — View and update local CLI configuration.
│   ├── set       — Set a configuration value.
│   └── show      — Print local CLI configuration as JSON.
├── feed          — Manage RSS/Atom feed subscriptions on the server.
│   ├── add       — Subscribe the server to an RSS/Atom feed.
│   ├── list      — List subscribed feeds on the server.
│   ├── remove    — Unsubscribe by feed ID or URL.
│   └── sync      — Trigger a server-side sync.
├── rotate-key    — Mint a new API key + update your local key file.
└── vault         — Backend config + health check.
    ├── backend
    │   ├── clear        — Forget the configured server.
    │   ├── set-server   — Point the CLI at an amperstand-core server.
    │   └── show         — Show the configured server URL + API key mode.
    └── status           — Show server health + total doc count.
```

`amperstand --help` only shows the top-level entries (typer is hierarchical by default). `commands` walks the whole tree — useful for grep, useful for discovery.

## Backend setup

Before any other command works, point the CLI at a server:

```bash
amperstand vault backend set-server http://your-server:8765 \
    --api-key-env AMPERSTAND_API_KEY

amperstand vault backend show           # see current config
amperstand vault backend clear          # forget the server
```

<Warning>
`--api-key-env` takes the **name** of an environment variable, not the value. The CLI stores the *name* in `~/.amperstand/config.json` and reads the value at runtime — so rotating the key is just `export AMPERSTAND_API_KEY=<new>`. Passing the value directly embeds it in the config file.
</Warning>

## Capture

```bash
amperstand capture <url>
```

POSTs the URL to `/capture`. Server runs the right extractor and persists the markdown into the vault. Returns the saved doc's ID and path.

| Option | What |
| --- | --- |
| `--no-persist` | Extract only — don't save in the vault |

For richer flows (async extraction, capture from pre-rendered HTML, capturing `.eml` files), call the [HTTP API](/api-reference/capture) directly.

## Feeds

```bash
amperstand feed add <url>           # subscribe (POST /feeds/register)
amperstand feed remove <feed-id>    # unsubscribe (DELETE /feeds/{id})
amperstand feed list                # show subscriptions + last sync (GET /feeds)
amperstand feed sync                # trigger a server-side sync (POST /feeds/sync)
```

`feed remove` also accepts the feed URL — the CLI looks it up in the server's list and resolves the ID for you.

Feed polling runs on a cron on the server; `feed sync` just kicks it manually.

## Vault

```bash
amperstand vault status         # GET /health + doc count
```

That's it for vault-level commands today. Per-doc operations (get / update / delete) go through the [HTTP API](/api-reference/vault-docs) directly.

## Config

```bash
amperstand config show          # dump ~/.amperstand/config.json
amperstand config set <key> <value>
```

The CLI's config is small: the server URL, the API key env-var name, and log settings. Vault state (feeds, allowlists, captured-URL history) lives on the server, not in `~/.amperstand`.

## What the CLI doesn't do

Things you might expect but should reach for elsewhere:

| You want… | Use… |
| --- | --- |
| Run an IMAP fetch loop | `amperstand-email-watch.service` on the server (systemd unit; see [Deployment](/deployment)) |
| Manage the email-sender allowlist | `amperstand-admin` on the server |
| Search or read docs | The [HTTP API](/api-reference/vault-search) — no CLI commands for this today; pipe `curl` and `jq` |
| Capture from local HTML or an `.eml` file | The [HTTP API](/api-reference/capture) — `/capture/html` or `/email/parse` |
| Write directly to a local folder | Not supported. The CLI is an HTTP client; the vault lives on the server. If you want files on your laptop, `rsync` the server's vault directory or mount it. |

## Server-side admin

`amperstand-admin` is a **separate** CLI that ships with `amperstand-core` and runs **on the server**, not your laptop. SSH to the server to use it. Operates on the vault filesystem + SQLite directly, bypassing HTTP.

Common operations:

```bash
amperstand-admin rotate-key --env-file /etc/amperstand/env   # create/rotate the API key
amperstand-admin reindex                                     # rebuild meta.db from markdown
amperstand-admin vec-rebuild                                 # backfill semantic embeddings
amperstand-admin integrity --deep                            # verify vault is consistent
amperstand-admin backup /tmp/vault-snapshot.tar.gz           # tar the data dir
amperstand-admin stats                                       # vault size + health
```

Full reference: [Admin CLI](/admin-cli).
