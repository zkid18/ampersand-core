## What it is

Amperstand is a **self-hosted personal vault** — a small server you run that:

- Captures web content (articles, YouTube, RSS, newsletter emails) into clean markdown files you own
- Stores them in a folder on disk with a SQLite index for FTS5 + vector + hybrid search
- Exposes a REST API any client can talk to

You run it once on a $4 droplet (or your home server), then connect any number of clients: a CLI on your laptop, a Telegram bot, a Chrome extension, your own agent code. They all share one vault.

## Architecture

```
   ┌──────────────────┐
   │  amperstand      │  ← CLI on your laptop
   │  (HTTP client)   │
   └─────────┬────────┘
             │
   ┌─────────┴────────┐    ┌──────────────┐
   │  Telegram bot    │    │  Chrome ext  │
   └─────────┬────────┘    └──────┬───────┘
             │                    │
             └──────────┬─────────┘
                        │ HTTP + Bearer auth
                ┌───────▼──────────┐
                │                  │
                │  amperstand-core │  ← the server you run
                │   (FastAPI)      │
                │                  │
                │ ┌──────────────┐ │
                │ │ extractors   │ │
                │ │ vault store  │ │
                │ │ feed registry│ │
                │ │ job queue    │ │
                │ │ FTS5 + vec   │ │
                │ └──────────────┘ │
                └────────┬─────────┘
                         │
                  ┌──────▼────────┐
                  │  ~/vault/     │   ← markdown files
                  │  vault.db     │   ← SQLite index
                  └───────────────┘
```

Every client speaks HTTP. The server is the only thing that touches your vault files.

## What it captures

| Surface | Extractor |
| --- | --- |
| Articles & blog posts | trafilatura, Playwright fallback for JS-heavy pages |
| YouTube videos | `yt-dlp` metadata + transcript API + optional Whisper fallback |
| LinkedIn posts | URL-shape extractor |
| Twitter / X | `fxtwitter` rewrite + thread reconstruction |
| RSS / Atom feeds | `feedparser` + per-item extraction |
| Newsletter emails | `.eml` parsing, IMAP fetch loop |

All extraction runs **on the server**. Clients just hand over a URL (or HTML, or an .eml file) and wait for the result.

## Why this shape

- **One vault, many clients.** Capture from your phone via Telegram, one-click from the browser, batch from a script — everything lands in the same searchable store.
- **Data sovereignty.** The vault is plain markdown files on a server you own. The tool can disappear; the files don't.
- **Stable surface.** The HTTP API is the contract. Build any client in any language. Your own agents query the same endpoints the bot does.
